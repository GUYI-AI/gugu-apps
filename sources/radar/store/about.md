让 agent 关注别的 agent。被关注的那个出了事，雷达给收提醒的人发一条消息。关注分三档，每一档都包含前一档：

| 档位 | 什么时候提醒 |
|---|---|
| 出问题（默认） | 它停下来报错了；它不在了（引擎意外退出，或者任务被归档、删除）；它好像卡住了：还在干活，但 30 分钟（可以改）没有新动作。卡住只对开着的面板 agent 判，终端 agent 和没打开的面板 agent 看不到最后一次动作，不判 |
| 需要你 | 上面这些，再加上它在等人批准一个操作、回答问题、看计划或处理对话框 |
| 全部 | 上面这些，再加上它每做完一轮，消息里带上它最后说的话（最多 1500 字） |

同一件事只提醒一次，要等被关注的 agent 下一次开始干活才会再提醒。消息标着「来自 雷达」，不用回复。提醒用咕咕当时的界面语言写（中文或英文）。

被关注的或者收提醒的那个任务不在了（归档、删除），这条关注就到此为止，自动删掉；这条路已经送到的次数还留着，以后同一对再关注会接着数。

## 怎么用

在任务里跟 agent 说「盯着那个任务，出事告诉我」「它做完了叫我」，agent 就会替你订一条关注，档位和收提醒的人都可以说。同一个人对同一个 agent 再订一次，改的是原来那一条。想停，跟 agent 说一声，或在页签的「正在关注」里点停止。

## 限制

- 「跑完」会把被盯 agent 最后说的话（最多 1500 字）原样转给收信方，收信方可以是第三个 agent。订之前想清楚谁该看到它。
- 后台页没在跑的那段时间（咕咕关着、雷达刚装上或刚重启），发生的事会漏掉：后台起来后的第一眼只记下当时的状态，不和之前比，所以不会补报。
- 可关注同一账号各台电脑上的 agent，也可把提醒交给另一台电脑上的 agent。别的电脑每 30 秒读一次，提醒带电脑名和读数时间；那台电脑离线时关注保留，不当成任务没了。
- 没有窗口的咕咕服务器上也能跑，需要服务器上装有 Chrome 或 Chromium。
- 另一台电脑上的 agent 暂时读不到它最后说的话，跨电脑的「跑完」提醒会写明这一点。
- 有人主动停掉一条正在跑的任务，雷达既不当出错、也不当跑完。

## 页签

顶栏显示当前图的状态计数和后台心跳；提醒按天分组，可筛选出问题、等人或做完的记录，未送达时标明原因。「正在关注」列表显示目标、档位与次数，可直接停止关注。点节点查看状态和关注关系，点连线查看提醒路径。窄栏中图在上、提醒和关注在下。

任务里打开时是以这个任务的 agent 为中心的局部图（看 1–3 层），否则是整张图。点是 agent，颜色是它此刻的状态；一条线是一条提醒走的路，从被关注的 agent 指向收提醒的人，线上的数字是这条路已经送到过几次（0 次不写）。送出一条提醒时，一个光点沿线跑过去，到了以后数字加一并跳一下；没送到的光点在半路碎掉，线变红。背景有几道静止的、很淡的同心圆，只用来示意中心（局部图围着这个任务，整张图围着所有点的中间）。状态也用动效表达：在干活的点在呼吸，等你批准的点有慢脉冲，出问题的点变红并抖一下，闲着的点偏淡，不在了的点半透明、虚线描边。悬停时，它和它的邻居保持亮着，其余的淡下去。悬停或点开时，用一整句话说清是谁让谁在什么时候收到提醒、提醒过几次。可以拖动节点、滚轮缩放、拖背景平移。系统开着「减少动态效果」时，这些动效都不出现，图一次排好。点节点后的「打开这个任务」会跳到那个任务。
