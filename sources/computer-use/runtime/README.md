# Computer Use App native layer

This module owns the native implementation. It is not another Gugu native host.

- `prepareDriver` prepares a pinned platform-specific driver only inside a supplied App data directory. Archive hashes are verified before bounded extraction; link/path overrides are refused. Cached executables are compared with their verified archive, executable bits are restored, architecture and macOS signature are checked, and the pinned driver version is probed. No default host-native directory is searched. Concurrent preparation subscribers cancel independently; only departure of the last subscriber aborts shared work.
- `createCuaClient` preserves the maintained daemon protocol, per-owner channels, environment allowlist, native cancellation and bounded observation. Startup cancellation/timeout closes metadata and owner-control sockets or the Windows proxy, and retires an unused daemon; another waiting caller retains its own work. Image sampling accepts the App's decoder adapter; it never imports Electron.
- `createComputerTools` accepts native documentation and trusted caller context from the App's program adapter. Arguments cannot select another machine/owner. Protected host identity and macOS permission checks fail closed. Permission preflight calls the actual driver with `prompt:false`, never the helper; screenshot-producing calls require Screen Recording, including file/debug outputs on individual tools or batch steps; explicit tree-only observations without file outputs can run with Accessibility alone. Nested batch steps obey the same foreground-fallback confirmation rule as individual tools. A missing permission or required foreground/destructive confirmation returns immediately with the blocker and next step. The agent decides whether to use its existing AskUserQuestion or conversation; after explicit approval it can retry with `confirmed: true`. That flag is the agent's assertion of prior approval, not an App-created approval or an independently verified human answer. No App-specific human waiter or request interface exists.
- `createPermissionClient` runs only the bundled, verified helper and exposes only `openSettings` for the two fixed macOS settings panes. It has no status or grant API, including in the native executable. Page status and subsequent permission refreshes must use the running driver's `check_permissions` with `prompt:false`. Opening settings does not grant permission. The bundled helper has an ad-hoc signature, not Developer ID/notarization.
- `createComputerControl` preserves target-specific pause and now aborts in-flight operations on disposal and rejects subsequent work. Program-wide revocation must dispose the App's runtime; cancelling one call supplies only that call's signal.

Build the JavaScript with `npm run build:runtime`. Build permission resources on macOS with `npm run build:permissions`; it requires the normal Xcode command-line toolchain and emits both architectures into one ad-hoc-signed helper. `npm test` checks the committed JavaScript, provenance, helper source hash, bounded resource preparation, policy and lease behavior. `npm run test:mutations` independently removes revocation, bound-task identity and checksum enforcement in temporary source copies, and requires the positive checks to fail.

`native/check-driver.mjs` requires an explicitly isolated `GUGU_EXTENSION_DATA_DIR`; it verifies/downloads the native driver and inspects version/documentation without starting its daemon or manipulating windows. This is not a real input, capture, system-permission grant/revoke or remote transport acceptance test.

This layer leaves the current market manifest unchanged. Program entry/cancellation integration, the approved page and transport, real-window acceptance, old-manifest compatibility and removal of Computer Use-specific Gugu implementation follow in separate reviewed layers. There is no host-native fallback in this runtime.

Decision: the owner already has AskUserQuestion and rejected an additional “needs you” mechanism because waiting browser tools blocked normal messages. Tools report blockers and return; they do not wait for people inside a tool call.

`native/check-macos-runtime.mjs` is an opt-in actual-driver check (`GUGU_TEST_NATIVE_MAC=1` plus absolute isolated `GUGU_HOME`, `GUGU_USER_DATA_DIR`, and `GUGU_EXTENSION_DATA_DIR`). It opens an owned native fixture window, reads driver status without prompts, captures only that exact pid/window, saves evidence, and closes its owned processes. It does not change system grants or establish the final installed App MCP/TCC attribution; that launch chain is verified after program integration.
